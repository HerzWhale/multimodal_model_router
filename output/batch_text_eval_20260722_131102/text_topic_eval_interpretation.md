# 清理后 18 条文本主分类评估解读

## 1. 本批次回答什么问题

本批次用于验证：在模型可见文本中移除主分类答案提示后，DeepSeek 能否按照项目既定的 9 类内容分类规则，为更接近内容平台素材形态的文本生成稳定主分类。

本次输入严格限定为 `evaluation/text_topic_small_set/` 中的 18 条文本，没有处理默认业务输入，也没有处理图片或视频。18 条样本覆盖 9 个主分类，每类 2 条；其中 4 条长难例约为 850—950 个中文字符。

## 2. 核心结果

| 指标 | 结果 | 解读 |
|---|---:|---|
| 已评估样本 | 18 | 18 条样本均有人工标准答案并纳入统计 |
| 正确样本 | 14 | 14 条模型主分类与人工标准答案一致 |
| Accuracy | 77.78% | 反映本批次全部样本的总体命中比例 |
| Macro-F1 | 73.70% | 对 9 个分类的 F1 等权平均，低于 Accuracy，说明分类间表现不均衡 |
| 模型调用 | 18 次 | 每个文本文件触发 1 次 DeepSeek 文本分析 |
| 调用错误 | 0 | 18 次调用均成功返回并写入结果 |
| 总成本 | 0.021542 元 | 本批次实际记录的 DeepSeek 调用成本 |
| 平均单文件成本 | 0.001197 元 | 总成本除以 18 个文件 |
| 平均模型延迟 | 4563.56 ms | 18 次真实模型调用的平均耗时 |
| P95 模型延迟 | 6294 ms | 约 95% 的模型调用延迟不超过该值 |

本批次的 18 次文本分析全部来自 `deepseek-v4-flash`，没有 mock 模型调用。因此，以上文本分类、成本和延迟数据是真实调用证据；它们不代表图片、视频上游模型已经真实接入。

约束判断：本批次总成本只占50元预算上限的约0.0431%，成本约束宽松；但6294ms的 P95 模型延迟高于文本任务原定2000ms上限，延迟约束未通过。调用成功不等于性能达标。

## 4. 四条错例说明

1. `11_news_entertainment_film_festival_incident.txt`：人工标准答案为 `news`，模型预测为 `entertainment`。模型更关注电影节和明星语义，没有把“活动临时取消、主办方回应、安全管控”作为新闻事件的主业务归属。
2. `12_knowledge_with_soft_ad_nutrition.txt`：人工标准答案为 `knowledge`，模型预测为 `lifestyle`。模型识别了控糖和食品选择的生活属性，但没有遵循“以知识讲解为主体时归入知识科普”的边界规则。
3. `17_other_long_campus_lost_found.txt`：人工标准答案为 `other`，模型预测为 `lifestyle`。校园事务通知不属于八个明确主题，但模型倾向选择语义上最接近的生活类。
4. `18_other_long_community_coordination.txt`：人工标准答案为 `other`，模型预测为 `knowledge`。社区工具借用流程同样属于兜底类，模型把说明性内容误当成知识讲解。

这些错例说明，当前分类器不是“完全不可用”，而是存在两个可定位的问题：一是事件形式和领域内容发生冲突时，主业务归属规则执行不稳定；二是模型倾向把兜底内容强行归入相邻类别，导致 `other` 召回为 0。

## 5. 这次结果能证明什么

- DeepSeek 真实文本分析、人工标准答案合并、分类指标生成、成本记录和延迟记录已经形成可复现闭环。
- 在这 18 条无答案提示样本上，模型能够正确识别 14 条，并在广告、财经、体育健康、科技四类上全部命中。
- 分类级指标能揭示总体 Accuracy 看不到的问题；如果只看 77.78%，就会遗漏 `other` 完全没有召回这一关键风险。
- 当前错例可以直接反向指导分类提示词和规则优化，而不是继续扩展新功能。

## 6. 不能证明什么

- 18 条样本仍然很小，每类只有 2 条，单条错例就会显著改变分类级指标。
- 样本是参考内容平台常见形态后人工改写，不是从线上生产流量随机抽样，不能代表真实内容分布。
- 本次只评估主分类，不评估摘要、关键词、副分类和业务用途的质量。
- 本次没有图片、视频真实上游模型调用，不能证明多模态理解质量。
- 本次只使用一个 DeepSeek 模型，不能用于比较不同供应商或模型组合的质量。
- 当前串行批处理的 P95 模型延迟没有达到文本任务2秒以内的目标，不能宣称满足低延迟场景。

## 7. 当前功能闸门判断

文本主分类评估工程链路已经通过闸门：真实代码可运行、真实 API 调用成功、人工标准答案和模型预测可对齐、Accuracy 与 Macro-F1 可复现、成本和延迟可追踪、错误边界可定位。

文本主分类质量仍不应宣称“已经做好”。下一步应继续留在同一功能内，先复核 4 条错例的人工分类规则，再针对“新闻与领域冲突”“知识与生活冲突”“兜底类拒绝归类”三个边界做最小提示词修正。只有修正规则后用一组不参与调试的新样本复测，才能判断质量是否真正提升。
