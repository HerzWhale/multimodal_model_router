# 失败与部分成功演示解读

本文件用于解释 `batch_failure_demo_20260721_190052` 这次离线故障演示。它的目的不是测试真实模型质量，而是证明系统能在上游模型失败或关键模型失败时，保留状态、错误、缺失证据和风险提示。

## 1. 本批次演示了什么

本批次使用现有 `input/` 样例文件，显式注入 3 类故障：

| 文件 | 媒体类型 | 注入故障 | 最终状态 | 解释 |
|---|---|---|---|---|
| `img.png` | 图片 | OCR 失败 | `partial_success` | OCR 失败导致 `ocr_text` 缺失，但视觉理解仍成功，文本分析仍能基于画面描述产出结果 |
| `ai_content_sample.txt` | 文本 | 文本分析失败 | `failed` | 文本分析是最终结构化输出的关键步骤，失败后无法产出主分类、标签和摘要 |
| `例子.mp4` | 视频 | 语音识别失败 | `partial_success` | 音频转写缺失，但 OCR 和视觉理解仍成功，文本分析仍能基于剩余证据产出结果 |

## 2. 为什么这不是普通 Demo

普通 Demo 往往只展示成功路径。本批次展示的是更接近工程系统的问题：

- 上游证据提取失败时，系统是否能继续利用其他证据；
- 哪些失败会导致 `partial_success`，哪些失败会导致 `failed`；
- 最终结果是否记录了缺失证据；
- 错误是否能通过 `errors.jsonl` 和 `model_calls.jsonl` 追踪到具体模型调用；
- 使用者是否能通过 `warning_messages` 判断结果可信度。

## 4. 面试时可以怎么讲

可以这样讲：

> 我没有只展示成功样例，还专门做了一个失败与部分成功批次。比如图片 OCR 失败时，系统不会直接把整个文件判死，而是保留视觉理解证据继续分析，并把状态标成 partial_success；但如果文本分析失败，系统就会判为 failed，因为无法产出最终的 topic、tags 和 summary。这个批次能说明我在设计时关注的不只是模型输出，还包括证据链完整性、错误定位和结果可信度。

## 5. 字段说明

| 字段 | 含义与作用 |
|---|---|
| `processing_status` | 文件级处理状态，用于区分成功、部分成功和失败。 |
| `missing_evidence` | 缺失证据列表，用于说明最终分析少用了哪些上游信息。 |
| `quality_flags` | 机器可读风险标签，用于批量统计和筛选问题样本。 |
| `warning_messages` | 面向使用者的风险提示，用于解释结果可信度为什么下降。 |
| `error_message` | 技术错误信息，用于定位失败原因。 |
| `call_id` | 单次模型调用编号，用于从文件结果反查具体失败调用。 |
| `task_type` | 模型调用任务类型，用于判断故障发生在 OCR、语音识别、视觉理解还是文本分析。 |
