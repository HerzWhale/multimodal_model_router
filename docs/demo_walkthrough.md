# Demo Walkthrough

这份文档用于解释当前 Demo 如何运行、输出文件怎么看，以及面试时如何讲清楚它的价值。

## 1. Demo 批次路径

当前可展示批次：

```text
H:\实习\multimodal_model_router\output\batch_20260718_150348
```

这个批次是项目当前最适合展示的样例，因为它同时包含文本、图片和视频三类输入，并生成了人工可读结果、模型调用明细和批次统计报告。

## 2. 输入样例说明

本批次来自项目的 `input` 目录，包含 3 个样例文件：

| 输入文件 | 类型 | 在 Demo 中的作用 |
|---|---|---|
| `ai_content_sample.txt` | 文本 | 展示文本读取、文本分析、分类、摘要和业务用途生成 |
| `img.png` | 图片 | 展示图片文件进入 OCR、视觉理解和文本分析流水线；当前 OCR 和视觉理解为 mock |
| `例子.mp4` | 视频 | 展示视频文件进入预处理、OCR、视觉理解、语音识别和文本分析流水线；当前视频上游处理为 mock |

相关字段说明：

| 字段 | 含义与作用 |
|---|---|
| `file_name` | 原始文件名，用来让使用者识别每条结果对应哪份内容 |
| `media_type` | 文件媒体类型，用来决定进入文本、图片还是视频流程 |
| `source_path` | 原始文件路径，用来追溯输入文件来源 |

## 3. 运行命令

进入项目目录：

```powershell
cd H:\实习\multimodal_model_router
```

安装依赖：

```powershell
pip install -r requirements.txt
```

如果要复现真实 DeepSeek 文本分析，需要先在本机设置环境变量：

```powershell
$env:DEEPSEEK_API_KEY = "你的 DeepSeek API Key"
```

然后运行：

```powershell
python .\src\main.py
```

运行后，系统会在 `output` 目录下创建新的批次文件夹。每个批次文件夹的名字都包含运行时间，例如 `batch_20260718_150348`。

## 4. `results_readable.md` 怎么读

`results_readable.md` 是给人看的文件级结果说明。它把每个文件拆成一个独立段落，适合直接截图或面试展示。

重点看这些信息：

| 字段或展示项 | 含义与作用 |
|---|---|
| `file_id` | 单个文件的唯一标识，用来关联最终结果和模型调用记录 |
| `processing_status` | 文件处理状态，用来判断该文件是否成功生成结果 |
| `topic` | 主分类，用来说明内容最主要的业务归属 |
| `secondary_topics` | 副分类，用来说明内容是否存在交叉领域 |
| `tags` | 关键词，用于后续搜索、筛选和素材管理 |
| `summary` | 内容摘要，用于快速理解文件内容 |
| `business_use` | 业务用途说明，用来解释这个结构化结果可以支持什么业务动作 |
| `evidence_used` | 实际使用的证据，用来判断结果是基于原文、OCR、语音转写还是视觉描述 |
| `missing_evidence` | 缺失证据，用来说明结果可信度可能受到什么影响 |
| `models_used` | 文件级模型使用摘要，用来快速看到这个文件经过哪些模型 |
| `processing_cost_cny` | 文件级处理成本，单位人民币 |
| `processing_time_ms` | 文件级处理耗时，单位毫秒 |

本批次中最适合展示的是文本文件 `ai_content_sample.txt`：它的文本分析由 DeepSeek 真实生成，输出了 `technology` 主分类、`knowledge` 副分类、5 个关键词、摘要和业务用途。

图片和视频结果要如实说明：它们展示的是流程跑通和输出结构，OCR、视觉理解、语音识别仍是 mock，因此不能把这部分说成真实多模态理解结果。

## 5. `batch_report.json` 怎么读

`batch_report.json` 是批次级统计报告，用来回答“这批任务整体表现如何”。

本批次核心结果：

| 指标 | 数值 | 含义 |
|---|---:|---|
| 总文件数 | 3 | 本批次处理了 3 个输入文件 |
| 成功文件数 | 3 | 3 个文件都生成了文件级结果 |
| 成功率 | 100% | 成功文件数除以总文件数 |
| 总成本 | 0.042107 元 | 本批次全部模型调用成本合计 |
| 平均每文件成本 | 0.014036 元 | 总成本除以文件数 |
| 平均文件处理耗时 | 2154.33 ms | 文件级处理耗时平均值 |
| 模型调用 P95 延迟 | 3425 ms | 8 次模型调用中 95 分位延迟 |
| 最慢文件 | `file_0002` | 本批次中耗时最高的文件 |

关键字段说明：

| 字段 | 含义与作用 |
|---|---|
| `file_stats` | 文件处理统计，用来查看总数、成功数、失败数和成功率 |
| `cost_stats` | 成本统计，用来查看总成本、平均成本、供应商成本和预算使用率 |
| `latency_stats` | 延迟统计，用来查看平均耗时、P95 延迟和最慢文件 |
| `error_quality_stats` | 错误和质量统计，用来查看失败原因、质量风险和部分成功原因 |

## 6. `model_calls.jsonl` 怎么读

`model_calls.jsonl` 是模型调用明细。它不是给业务方快速阅读的，而是给技术负责人追踪成本、延迟和模型链路的。

每一个 JSON 对象表示一次模型调用。本批次共有 8 次调用：

| 文件 | 调用链路 |
|---|---|
| `img.png` | mock OCR → mock 视觉理解 → DeepSeek 文本分析 |
| `ai_content_sample.txt` | DeepSeek 文本分析 |
| `例子.mp4` | mock OCR → mock 视觉理解 → mock 语音识别 → DeepSeek 文本分析 |

关键字段说明：

| 字段 | 含义与作用 |
|---|---|
| `call_id` | 单次模型调用的唯一标识，用来区分同一文件触发的多次调用 |
| `batch_id` | 批次唯一标识，用来把多次文件处理归到同一批任务下 |
| `file_id` | 文件唯一标识，用来把模型调用和最终文件结果关联起来 |
| `task_type` | 模型调用任务类型，例如 OCR、视觉理解、语音识别或文本分析 |
| `provider` | 模型供应商，用来做供应商维度成本和延迟统计 |
| `model_name` | 具体模型名称，用来追踪结果来自哪个模型 |
| `input_units` | 输入用量和单位，例如输入 token、图片数量、帧数或音频秒数 |
| `output_units` | 输出用量和单位，例如输出 token 或文本字符数 |
| `cost_cny` | 单次调用成本，单位人民币 |
| `latency_ms` | 单次调用延迟，单位毫秒 |
| `status` | 单次调用状态，用来判断该调用成功还是失败 |
| `error_message` | 错误信息；成功时为空，失败时用于排查原因 |

注意：当前文件采用缩进式写法，方便人工阅读；系统内部读取逻辑已经兼容这种格式。

## 7. `model_strategy_report.md` 和 `model_strategy_report.json` 怎么读

阶段 4 新增了决策层报告，用来回答“看完这个批次后，技术负责人能怎么判断模型组合”。

这两个文件都来自已有 Demo 批次：

```text
H:\实习\multimodal_model_router\output\batch_20260718_150348\model_strategy_report.md
H:\实习\multimodal_model_router\output\batch_20260718_150348\model_strategy_report.json
```

生成命令：

```powershell
python .\src\model_strategy_advisor.py output\batch_20260718_150348
```

这条命令只读取既有 `batch_report.json` 和 `model_calls.jsonl`，不会重新跑批处理，也不会触发 DeepSeek API。

推荐阅读顺序：

| 报告部分 | 读法 | 能回答的问题 |
|---|---|---|
| 批次概览 | 先看文件数、成功率、总成本、平均延迟和 P95 延迟 | 这批任务整体规模和表现如何 |
| 成本分析 | 看任务类型、供应商和模型维度的成本占比 | 哪些任务或模型贡献了主要成本 |
| 延迟分析 | 看最慢调用、DeepSeek 平均延迟和 P95 来源判断 | 当前瓶颈大概率在哪里 |
| 质量与可信度边界 | 看真实调用数、mock 调用数、能证明什么和不能证明什么 | 哪些结论可以讲，哪些不能夸大 |
| 模型组合建议 | 看预算敏感、延迟敏感、质量优先三种建议 | 面对不同目标应该怎么选下一步路线 |
| 后续路线 | 看低成本、平衡、高质量和 live test 路线 | 项目下一阶段如何继续扩展 |

关键字段说明：

| 字段 | 含义与作用 |
|---|---|
| `model_call_count` | 模型调用次数，用来衡量本批次实际触发了多少次 OCR、视觉理解、语音识别或文本分析任务 |
| `cost_share` | 成本占比，用来判断某个任务、供应商或模型是否是主要成本来源 |
| `is_mock` | 是否为 mock 调用，用来区分真实模型调用和占位调用 |
| `real_model_calls` | 真实模型调用汇总，用来说明当前 Demo 哪些部分可以作为真实模型证据 |
| `mock_model_calls` | mock 调用汇总，用来说明当前 Demo 哪些部分只能证明流程跑通 |
| `missing_data_notes` | 数据缺失说明，用来提示某些报告字段无法从现有批次中取得 |

当前报告的核心结论是：这个 Demo 已经能证明 DeepSeek 文本分析、调用记录、成本核算、延迟追踪和策略解读链路跑通；但图片和视频上游仍是 mock，因此不能把图片/视频输出当成真实多模态质量结论。

## 8. 本批次成本、延迟、成功率

| 维度 | 数值 | 解读 |
|---|---:|---|
| 文件数 | 3 | 文本、图片、视频各 1 个 |
| 模型调用数 | 8 | 其中 DeepSeek 文本分析 3 次 |
| 成功率 | 100% | 所有文件都生成了最终结果 |
| 总成本 | 0.042107 元 | 包含 mock 上游计费和真实 DeepSeek 文本分析计费 |
| DeepSeek 文本分析成本 | 0.002107 元 | 本批次真实模型调用的成本估算 |
| P95 模型调用延迟 | 3425 ms | 主要由真实 DeepSeek 文本分析贡献 |

这个结果适合用来说明项目已经具备成本与延迟追踪能力，但不适合用来比较不同真实供应商的效果，因为当前尚未真实接入多个供应商。

## 9. 哪些是真实模型结果

当前真实模型结果主要来自 DeepSeek 文本分析。

真实部分包括：

- 基于文本证据生成 `topic`，也就是内容主分类。
- 生成 `secondary_topics`，也就是最多两个副分类。
- 生成 `tags`，也就是最多五个关键词。
- 生成 `summary`，也就是 300 字以内摘要。
- 生成 `business_use`，也就是结构化结果可能支持的业务用途。
- 返回输入 token 和输出 token 用量，并用于估算真实调用成本。
- 记录真实调用延迟。

## 10. 哪些是 mock

当前 mock 或占位部分包括：

| 任务 | 当前状态 | 说明 |
|---|---|---|
| OCR | mock | 返回模拟文字，不是真实图片文字识别 |
| 视觉理解 | mock | 返回模拟视觉描述，不是真实图像理解 |
| 语音识别 | mock | 返回模拟音频转写，不是真实音频识别 |
| 视频预处理 | 占位 | 用于跑通关键帧和音频链路，不代表完整视频理解 |
| 多供应商动态路由 | 未实现 | 目前按任务类型固定路由，不按成本、延迟或质量动态选择 |

面试时不要把图片和视频结果说成真实识别效果。更准确的说法是：当前已经把多模态批处理的工程骨架、统一输出、成本延迟追踪和 DeepSeek 文本分析真实调用跑通；真实图片和视频理解是下一阶段计划。

## 11. 面试时如何讲这个 Demo

可以按这条线讲：

1. 先讲业务问题：内容平台有大量图文视频素材，处理时需要统一输入、统一输出，并知道每次模型调用的成本和延迟。
2. 再讲你的拆解：我把一个文件拆成文件识别、上游证据提取、文本分析、结果写入、模型调用记录和批次报告几个环节。
3. 展示 `results_readable.md`：说明它是给人看的结果页，可以快速看到每个文件的分类、摘要、证据、成本和耗时。
4. 展示 `model_calls.jsonl`：说明每次模型调用都有 `call_id`，可以追踪供应商、模型、用量、成本、延迟和状态。
5. 展示 `batch_report.json`：说明它把成本、延迟、成功率汇总到批次级，能帮助技术负责人做预算和模型选型判断。
6. 展示 `model_strategy_report.md`：说明它把已有批次统计进一步转成模型组合建议，例如预算敏感、延迟敏感和质量优先时分别怎么取舍。
7. 主动说明边界：当前真实接入 DeepSeek 文本分析，图片和视频上游仍是 mock；我没有夸成全真实多模态平台。
8. 最后讲下一步：接入真实 OCR、ASR 或视觉理解模型，增加失败样例和受保护 live test，让策略报告逐步变成真实模型组合决策工具。
